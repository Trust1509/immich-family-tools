# Ausnahmen fuer scripts/zeilenenden.sh (#104, #118).
#
# Eine Zeile je Ausnahme: <Pfad><TAB><erlaubter Wert>. Der Pfad ist exakt und
# wortwoertlich (kein Glob, kein Praefix- oder Muster-Vergleich, keine
# Gross-/Kleinschreibungs-Toleranz) -- er kommt aus der Fund-Zeile des
# Waechters (der Teil vor ": eol:") oder aus Feld 2 von `git ls-files --eol`,
# und zwar so, wie der Waechter selbst ihn liest: unter `core.quotePath=true`
# erzwungen, also in Gits C-Quoting, sobald der Pfad Sonderzeichen traegt
# (z. B. `"t\303\244st.txt"` statt `täst.txt`) -- unabhaengig davon, welchen
# `core.quotePath`-Wert die eigene Arbeitskopie zufaellig gesetzt hat (#118
# Nacharbeit 1). Der Wert ist der Wert, den `git check-attr` bzw.
# `git ls-files --eol` fuer GENAU diesen Pfad melden soll (z. B. `crlf`) --
# nicht "alles ausser lf": ein anderer Wert oder ein anderer Pfad bleibt ein
# Befund. Attribut- und Index-Seite teilen sich EINEN Wert je Pfad (siehe
# "BEKANNTE GRENZEN" im Kopf von zeilenenden.sh). Ein eingetragener Pfad, der
# nicht mehr versioniert ist, gilt selbst als Befund (veraltete Ausnahme) --
# ebenso ein doppelter Eintrag (der erste gewinnt, ist aber trotzdem ein
# Befund), ein drittes Feld oder ein leerer Pfad.
#
# Leere Zeilen und Zeilen, die mit `#` beginnen, werden uebersprungen. Ein
# Byte-Order-Mark vor dem allerersten Eintrag wird abgestreift, ein
# abschliessendes `\r` je Zeile ebenso (eine mit CRLF gespeicherte Datei
# griffe sonst unter Git-Bash anders als unter Linux).
#
# Heute: keine Ausnahmen.
